# Day 07：建立 RAG 评估基线

## 今日目标

建立一套可重复执行的评估集，用数据回答“检索是否变好、答案是否更准、代价是否可接受”。

## 今日时间表

1. 09:00-10:30：学习检索和生成指标。
2. 10:45-12:00：编写 50 至 100 条评估样本。
3. 14:00-15:30：实现检索评估脚本。
4. 15:45-17:00：实现答案和引用评估。
5. 17:00-18:00：保存基线报告。

## 必学知识

- `【非常重点】Recall@K`：目标证据是否进入前 K 个召回结果。
- `【非常重点】MRR`：第一个正确结果出现得有多靠前。
- `【非常重点】引用正确率`：引用是否真正支持回答。
- `【非常重点】评估集版本化`：优化前后必须使用同一批问题比较。
- `【重点】延迟与成本`：质量提升不能完全忽略 P50、P95 和 Token。

## 评估样本字段

```text
id
question
expected_answer
relevant_document_ids
relevant_chunk_ids
category
should_refuse
```

样本至少覆盖：精确事实、跨段综合、近义表达、多轮指代、无答案、权限隔离。

## 编码任务

1. 建立固定测试文档和问题集。
2. 自动计算 Recall@1、Recall@5 和 MRR。
3. 记录回答、引用、耗时和 Token。
4. 将失败样本分类为解析、切分、召回、排序、生成或权限问题。
5. 保存 JSON 原始结果和 Markdown 汇总报告。

## 验收标准

- 评估可以用一条命令重复运行。
- 每个指标有明确分母和计算方式。
- 保存当前 Baseline，后续不覆盖原始结果。
- 至少人工检查 20 条答案和引用。
