# Day 09：Reranker、Query Rewrite 与检索过滤

## 今日目标

使用宽召回加精排序提高最终上下文质量，并解决多轮指代和表达不完整的问题。

## 今日时间表

1. 09:00-10:30：学习 Bi-encoder 与 Cross-encoder 的区别。
2. 10:45-12:00：接入 Reranker。
3. 14:00-15:00：实现查询改写。
4. 15:00-16:00：加入元数据过滤与拒答阈值。
5. 16:00-18:00：重新评估并做消融实验。

## 必学知识

- `【非常重点】两阶段检索`：第一阶段高召回，第二阶段对少量候选精排序。
- `【非常重点】Reranker`：联合阅读 Query 和 Chunk，通常更准但计算更贵。
- `【非常重点】Query Rewrite`：把多轮上下文中的指代改写为独立可检索问题。
- `【非常重点】过滤先于检索`：用户、知识库和权限过滤不能依赖生成后处理。
- `【重点】消融实验`：分别关闭 Hybrid、Rewrite、Reranker，确认每个组件的真实贡献。

## 推荐流程

```text
原问题
-> 独立问题改写
-> 权限与元数据过滤
-> Dense + Sparse 宽召回
-> RRF 合并
-> Reranker 精排
-> 上下文构造
```

## 编码任务

1. 召回 20 至 30 个候选，Rerank 后保留 5 至 8 个。
2. 保存原问题与改写问题，方便调试。
3. Query Rewrite 失败时降级使用原问题。
4. 使用结构化字段表达过滤条件，禁止拼接未校验表达式。
5. 运行 Baseline、Hybrid、Hybrid+Rerank 三组评估。

## 验收标准

- 能解释为什么 Reranker 不直接扫描整个向量库。
- 多轮指代问题可以生成独立检索 Query。
- 用户过滤在向量检索阶段已经生效。
- 评估报告包含质量、延迟和成本对比。
