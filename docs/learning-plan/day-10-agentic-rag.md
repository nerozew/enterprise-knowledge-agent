# Day 10：使用 LangGraph 构建 Agentic RAG

## 今日目标

把知识库检索、灵感数据库和待办工具统一到一个可控工作流中，让系统按意图选择路径。

## 今日时间表

1. 09:00-10:30：设计 Graph State 和路由契约。
2. 10:45-12:00：实现意图分类与知识库路由。
3. 14:00-15:30：接入灵感查询和创建待办工具。
4. 15:45-17:00：加入检查、重试和人工确认。
5. 17:00-18:00：测试完整路径和失败路径。

## 必学知识

- `【非常重点】Workflow 与 Agent`：确定性步骤用边控制，真正需要模型决策时才交给 Agent。
- `【非常重点】状态契约`：节点输入输出字段必须清晰，避免把所有业务数据塞进 Messages。
- `【非常重点】Tool 副作用分级`：查询工具可自动执行，写入和删除工具需要确认。
- `【非常重点】循环终止条件`：设置最大步骤数、错误计数和安全退出路径。
- `【重点】失败降级`：检索失败、模型失败和工具失败应有不同处理。

## 建议工作流

```text
用户输入
-> 意图识别
   -> 知识问题 -> Query Rewrite -> Retrieval -> Rerank -> Generate
   -> 搜索灵感 -> search_ideas Tool
   -> 创建待办 -> 参数提取 -> interrupt -> create_todo Tool
   -> 普通对话 -> LLM
-> 统一响应
```

## 编码任务

1. 定义包含 `messages/intent/retrieved_chunks/pending_action/error` 的 State。
2. 为每条路径定义明确输入输出。
3. 写操作展示参数并暂停确认。
4. 工具错误进入统一错误节点，并保留可追踪信息。
5. 记录每次执行经过的节点、耗时和结果。

## 验收标准

- 四类请求稳定进入正确路径。
- 写操作未确认时不会执行。
- 不存在无终止条件的循环。
- 每次回答可以查看完整节点轨迹。
- Graph 节点可被独立单元测试。
