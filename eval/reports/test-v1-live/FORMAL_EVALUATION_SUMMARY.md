# RAG `test-v1` 100 题评估总结

## 1. 结论

本轮完成了 7 组真实 REST 链路实验，全部使用冻结的 `test-v1` 数据集。当前最均衡的基础检索配置是：

- Hybrid（Dense + Sparse）；
- Weighted Fusion，Dense 权重 `0.65`；
- `Top K = 5`，`Candidate K = 50`；
- Reranker 默认关闭；
- Query Rewrite 默认关闭；
- 生成答案时开启上下文扩展。

该基础检索配置在 80 道可回答题上取得：

- 文档 Recall@5：`100.00%`；
- 文档 MRR@5：`98.13%`；
- Source Span Recall@5：`100.00%`；
- Source Span MRR@5：`96.67%`；
- 检索延迟 P50 / P95：`154.2 ms / 225.7 ms`。

最终 ANSWER 链路在全部 100 题上完成 `100/100` 请求且无 HTTP 失败：

- 20 道不可回答题正确拒答率：`100.00%`；
- 错误接受率：`0.00%`；
- 80 道可回答题误拒率：`2.50%`（2 题）；
- 已接受答案的 Gold Citation Support Rate：`100.00%`；
- 总延迟 P50 / P95：`1.85 s / 2.71 s`。

### 3.1 选型判断

- Weighted Fusion 相比 RRF 提升文档与 Span 排序质量，同时本次测量的延迟更低，因此选为默认融合方式。
- Reranker 明显改善 Top 1 排序，但检索 P50 从 `154.2 ms` 增至 `427.6 ms`，约为 `2.77` 倍；并且 Span Recall@5 从 `100%` 降至 `99.38%`，说明它可能把多证据问题需要的片段挤出 Top 5。暂不作为默认路径。
- Query Rewrite 的文档 R@1 提升 `1.25` 个百分点，但 Span 指标没有提升，检索 P50 增至约 `7.24` 倍。适合作为低召回后的条件分支，而不是每次查询都执行。

## 4. 最终答案与拒答

最终配置为 `HYBRID + WEIGHTED(0.65) + CONTEXT_EXPANSION + ANSWER`，Reranker 和 Query Rewrite 关闭。

| 指标 | 结果 | 解释 |
|---|---:|---|
| Correct Refusal Rate | 100.00% | 20 道不可回答题全部拒答 |
| False Acceptance Rate | 0.00% | 不可回答题没有被错误放行 |
| False Refusal Rate | 2.50% | 80 道可回答题中 2 道被错误拒答 |
| Gold Citation Support Rate | 100.00% | 被接受答案均包含至少一个 Gold 支持引用 |
| Total P50 / P95 | 1.85 s / 2.71 s | 包含检索、证据门禁与答案模型 |

这里的引用支持率不等于答案所有 Claim 都已经完成人工蕴含检查；它表示评估脚本确认已接受答案至少引用了人工 Gold Source。

## 5. 失败案例

### `test-026`

问题：知识文档超过删除保留期后会清理哪些外部数据？

- 正确 `document-lifecycle` 片段排在 Top 1；
- Gold 原文明确包含“删除对象和向量”；
- 检索与证据预检已经通过；
- Qwen 答案模型仍返回 `model_refused`。

判断：这是答案模型误拒，不是召回失败。后续应改进结构化 Prompt、加入可回答性专用判定或对“Gold 片段 Top 1 且词法/语义门禁通过”的请求进行一次受限重试。

### `test-080`

问题：高风险灰度触发回滚并造成核心业务不可用时，发布和事故流程分别要求什么？

- `release-change` 的回滚片段排在 Top 1；
- `incident-response` 的 S1 定义片段排在 Top 3；
- 两个 Gold 文档与 Gold Span 均在 Top 5；
- 模型仍拒绝组合两个来源形成答案。

判断：这是多来源综合回答的误拒。后续应在 Prompt 中明确要求逐个子问题核对证据，并返回 `subclaims -> hit_ids` 的结构化映射。
